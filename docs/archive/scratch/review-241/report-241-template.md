### الإثبات — ثلاثُ حالاتٍ على الخطّاف المعدَّل نفسِه، قبل الالتزام

الملفُّ على القرص طابق المرفوعَ أولاً، والخطّافُ بقي `LF`، و`.gitignore` صار يعفيه:

```

```

**① سرٌّ مزروع في الملفّ المستثنى** — نسخةٌ من `seed.sql` زيد عليها سطرٌ يحمل `$argon2id$v=` وأُدرجت في الفهرس **بالمسار المستثنى نفسِه**، ثم شُغّل الخطّاف: رفضٌ **بالمحتوى** (لا بالنوع — فالنوعُ مُعفى):

```
  bench/external-review-2026-09/seed.sql  — يحتوي هاش كلمة مرور argon2id
HOOK_EXIT_planted=1
```

**② ملفُّ `.sql` آخر في المجلد نفسِه** — البايتاتُ النظيفة نفسُها أُدرجت باسم `other.sql` في المجلد ذاته: رفضٌ **بالنوع** — فالاستثناءُ مسارٌ لا مجلَّد:

```
  bench/external-review-2026-09/other.sql  — ملف SQL خارج مجلد الهجرات (مقلب قاعدة؟)
HOOK_EXIT_other=1
```

**③ الملفُّ الحقيقيّ** — أُدرج بـ`git add` بلا `-f` (فالتجاهلُ زال)، والخطّافُ يمرّ، وبصمةُ الـblob المُدرَج هي بصمةُ المرفوع:

```

HOOK_EXIT_real=0
index-blob sha256=830674019bfcdd010e02b77abd8260742fffedf39f2e9396b0eda95350c2dcdc
```

⚠️ **وحادثةٌ صغيرة في الإثبات نفسِه تستحقّ سطراً**: أولُ محاولةٍ للحالة ② لم تقع — `git rm --cached` رفض إزالةَ المزروع لأن محتواه يخالف القرصَ و`HEAD`، فبقي المزروعُ مُدرَجاً وقرأ الخطّافُ **رفضاً بالمحتوى** لا بالنوع؛ أي أن الحالة ② لم تُقَس في تلك الجولة وإن ظهر «رفض». قُرئ نصُّ الرفض لا رمزُه (`§8.12`: الأحمرُ يحتاج قراءةَ سببه كالأخضر) فأُعيدت الحالةُ بأداةٍ أخرى (`update-index --force-remove`) وجاء الرفضُ **بالنوع** مسمّياً `other.sql` — وهو المطلوب.
