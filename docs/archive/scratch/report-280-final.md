ترشيحي (أ). **لأن** ذلك المجلّدَ فيه أدواتٌ بأسماء أدوات ويندوز (`find` و`sort` وغيرهما)، فإضافتُه دائماً تغيّر ما تجده كلُّ نافذةٍ على الجهاز؛ والسطرُ لا يمسّ إلا نافذةَ الفحص.

• (أ) يُضاف إليهما حارسُ مسبارٍ كحارس الشهادة: يشغّل `bash` مرّةً قبلهما، فإن لم يردّ سقط برسالةٍ تقول: شغّل من Git Bash أو أضف مجلّدَ Git.

ترشيحي (أ) في أوّل طلب شيفرةٍ يمسّ إحداهما، لا طلباً وحدَه. **لأن** من يرى رسالة WSL يبحث في WSL، والسببُ في المسار؛ وليس عطلاً يُصلح بالقاعدة ٣٧ فالحزمتان تسقطان كما يجب ولا تبتلعان الغياب.

## ما وقع

**١. التشخيص.** قرأتُ القواعدَ الدائمة وتقريرَ ٢٧٩ ووقائعَه والدليلَ أوّلاً، ثم:
• من Git Bash بأمر الدليل نفسِه: 163 من 163 حزمة، و1055 من 1055 اختباراً. فالفشلُ لم يظهر.
• من PowerShell بـ`npx`: 3 حزمٍ و13 اختباراً سقطت، وهي العددان اللذان أبلغتَ بهما. والحزم: `certificate-expiry` و`deploy-recreate-guard` و`mail-dns-check`.
• **السبب:** هذه الحزمُ تشغّل `bash` و`openssl`. وفي PowerShell، `bash` اسمٌ مستعارٌ في ويندوز يفتح WSL، وتوزيعتُه الوحيدة على الجهاز `docker-desktop` وليس فيها `bash`؛ و`openssl` ليس في المسار أصلاً. والأداتان تأتيان مع Git في `C:\Program Files\Git\usr\bin`، والمسارُ يحمل مجلّدَ Git الآخر وحدَه. وفي السير (لينكس) وفي Git Bash كلتاهما حاضرة، فلا عطلَ في الشيفرة، والحرّاسُ أعلنت الغيابَ سقوطاً كما صُمّمت.
• **وعلّةٌ ثانية في الدليل نفسِه:** طريقُه حين تكون السكربتاتُ معطّلة `npx.cmd`؛ وبه لا يبدأ الفحصُ أصلاً ويقول «The system cannot find the file specified»، لأن الصيغةَ فيها العلامةُ `<` فيقرؤها `cmd` تحويلاً. وسياسةُ السكربتات على جهازك الافتراضيُّ فيها التعطيل، فهذا الطريقُ هو الذي ستسلكه نافذةٌ عاديّة.
