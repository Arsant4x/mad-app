## ٢) الحزمةُ الثالثة — أحكامُك الثلاثة وجوابا `ق-١٢٤٨`/② بالتجربة

**التجربة** على نسخةٍ من `schema.prisma` **خارج المستودع** (`D:\mad-app-scratch\review-246\prisma-probe\`)، بـ`prisma validate` و`migrate diff` مخطَّطاً إلى مخطَّط، على نموذجٍ واحد `Invoice → Customer`؛ **والإثباتُ على القاعدة** في معاملةٍ تُرجَع (`ROLLBACK`) على `mad_app` بدور المدير — لا أثرَ يبقى. التفصيلُ في `review-246\الحزمة-الثالثة-جوابا-ق-١٢٤٨.md`.

### أ) أيقبل Prisma مفرداً ومركّباً على `customerId` معاً؟ — **نعم**

```
VALIDATE_A_EXIT=0
DIFF_A_EXIT=0
CREATE UNIQUE INDEX "customers_companyId_id_key" ON "customers"("companyId", "id");
ALTER TABLE "invoices" ADD CONSTRAINT "invoices_companyId_customerId_fkey" FOREIGN KEY ("companyId", "customerId") REFERENCES "customers"("companyId", "id") ON DELETE RESTRICT ON UPDATE CASCADE;
VALIDATE_B_EXIT=0
DIFF_B_EXIT=0
ALTER TABLE "invoices" DROP CONSTRAINT "invoices_customerId_fkey";
```

A (**بجانب** القائم) يمرّ ويُبقي المفردَ ويضيف المركّبَ `RESTRICT`؛ B (**بدلَه**) يمرّ ويُسقط المفرد. **فحكمُ ① (الموضعُ في `schema.prisma`) لا يفرض «بدلَه»** — الاختيارُ قرارُ تصميم.

### ب) وما يتغيّر في `ON DELETE` للمئة والاثنين والخمسين؟ — **`SET NULL` هو الذي بلا بديل، لا `CASCADE`**

```
on_delete counts {"c":35,"r":87,"n":30}
on_update {"c":152}
VALIDATE_C_EXIT=0
ALTER TABLE "invoices" ADD CONSTRAINT "invoices_companyId_posShiftId_fkey" FOREIGN KEY ("companyId", "posShiftId") REFERENCES "pos_shifts"("companyId", "id") ON DELETE SET NULL ON UPDATE CASCADE;
VALIDATE_D_EXIT=0
ALTER TABLE "invoice_lines" ADD CONSTRAINT "invoice_lines_companyId_invoiceId_fkey" FOREIGN KEY ("companyId", "invoiceId") REFERENCES "invoices"("companyId", "id") ON DELETE CASCADE ON UPDATE CASCADE;
```

| الصنف | العدد | المركّب |
|---|---|---|
| `RESTRICT` | ٨٧ | ✅ يُعبَّر (A) |
| `CASCADE` | ٣٥ | ✅ يُعبَّر (D) — **لا واحدَ منها يفقد بديلَه** |
| **`SET NULL`** | **٣٠** | ⛔ **بلا بديلٍ مركّب**: Prisma يقبل `SetNull` على المركّب (C) **لكنّ Postgres يُصفّر كلَّ أعمدة المفتاح — و`companyId` منها وهو `NOT NULL`** |

**الإثباتُ على القاعدة** (مناوبةٌ عليها ثلاثُ فواتير):

```

{"shift":{"invoices":3},"delete":"FAILED:  Invalid `prisma.$executeRawUnsafe()` invocation: Raw query failed. Code: `23502`. Message: `Failing row contains (4e130735-6a88-41c4-ab24-ea2b212dbb0b, null, INV-2026-0397, 9e7cb84d-9ff7-41fd-8c6f-b625a3944277, 2026-09-08, 2026-09-08, PAID, 200.00, 30.00, 230.00, null, 2026-09-08 16:26:10.609, 2026","leftover_constraints":0,"single_fk_present_after_rollback":1}
```

- **بجانب المفرد**: الحذفُ ينجح — **بترتيب المُشغِّلات وحسب** (المفردُ يُصفّر `posShiftId` أولاً فلا يجد المركّبُ ما يُصفّره): تعايشٌ هشّ.
- **بدلَ المفرد**: الحذفُ يسقط `23502` — الصفُّ الفاشل `companyId` فارغ. **فلا يُحذف فرعٌ ولا مناوبةٌ ولا درجٌ** ما دام يشير إليه صفّ.

**الثلاثون** (١٦ منها `branchId → branches`): `bank_transactions.branchId · banks.branchId · branches.activityId · branches.propertyId · branches.warehouseId · cash_drawers.branchId · contracts.renewedFromId · employees.branchId · goods_receipts.branchId · handover_photos.itemId · inventory_write_offs.branchId · invoices.branchId · invoices.offlineIncidentId · invoices.posShiftId · journal_entries.branchId · maintenance_requests.unitId · maintenance_requests.warrantyId · payments.branchId · pos_shifts.branchId · pos_shifts.drawerId · products.activityId · purchases.branchId · quotes.branchId · reminder_policies.escalateToUserId · rent_accruals.paymentId · rent_payments.installmentId · stock_movements.branchId · supplier_payments.branchId · warranties.supplierId · warranties.unitId`.

**ثلاثةُ مخارجَ تُعرض ولا تُختار هنا**: ① تبقى مفردةً وتخرج من الحزمة صراحةً (تحرسها `RLS` والتطبيقُ كما اليوم) · ② `ON DELETE SET NULL (posShiftId)` — صيغةُ Postgres 15+ التي تُصفّر عموداً مسمّى، **لا يعبّر عنها Prisma** فتُكتب SQL في الهجرة كما `RLS` (ويُقاس إصدارُ القاعدة) · ③ تحويلُها إلى `RESTRICT` مع حذفٍ ناعم — تغييرُ سلوكٍ يُقاس على المستدعين.

**والحكمان الآخران كما أمرت**: ③ `permission_templates` يبقى على فحص الشيفرة (القوالبُ العامّة بلا `companyId`) ويُعلَن حدّاً في الموجز · 📌 مسحُ «ما يُكتب بلا قراءة» بندُ متابعةٍ يُقاس **بعد** البناء.
