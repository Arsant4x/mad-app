# ١. النطاق والغرض

## ١.١ ما الذي تغطيه هذه الوحدة

وحدة واحدة تخدم كل نشاط يملك **بضاعة مادية**، وهي في رِكز: التجزئة والجملة، الصيدليات،
المطاعم والكافيهات، معارض السيارات، قطع الغيار، التصنيع الخفيف، ومقاولات التوريد.
المستودع المستقل (شركة تخزين/لوجستيات) حالة خاصة تُعالَج في §١٧.

**المبدأ الحاكم (من `CLAUDE.md` §3):** المخزون **نواة مشتركة**، لا ملف نشاط.
الأنشطة لا تحصل على نسخة مستودع خاصة بها — بل على حقول وقواعد إضافية فوق نفس المحرّك.

# ٢. تصنيف كل ميزة: نواة أم ملف نشاط؟

> هذا الجدول هو البوابة الإلزامية قبل كتابة أي كود (`CLAUDE.md` §3).
> الخطأ في هذا التصنيف هو أغلى خطأ ممكن في هذه الوحدة.

| الميزة | التصنيف | السبب |
|---|---|---|
| الأصناف والمتغيّرات (لون/مقاس) | 🧱 نواة | تجزئة + قطع غيار + صيدلية |
| وحدات القياس وتحويلاتها (كرتون ↔ حبة) | 🧱 نواة | جملة + صيدلية + مطعم |
| طبقات التكلفة والتقييم | 🧱 نواة | كل نشاط ببضاعة |
| أرقام التشغيلة (Lot/Batch) | 🧱 نواة | صيدلية + أغذية + كيماويات + مطاعم |
| تواريخ الصلاحية و FEFO | 🧱 نواة | نفس ما سبق |
| الأرقام التسلسلية (Serial) | 🧱 نواة | إلكترونيات + سيارات + معدات |
| مواقع التخزين (Bins) | 🧱 نواة | يُفعَّل بمفتاح، معطَّل افتراضياً |
| التكلفة الوصولية (Landed Cost) | 🧱 نواة | كل مستورد |
| بضاعة الأمانة (Consignment) | 🧱 نواة | جملة + سيارات + صيدلية |
| التجميع/التفكيك (Kit / Bundle) | 🧱 نواة | تجزئة + مطاعم + جملة |
| الجرد الدوري والمستمر | 🧱 نواة | كل نشاط |
| نقاط إعادة الطلب والمخزون الآمن | 🧱 نواة | كل نشاط |
| رقم الهيكل (VIN) ودفتر المركبة | 🎭 معارض السيارات | حقل معنى واحد فقط |
| الوصفة وتكلفة الطبق | 🎭 مطاعم | يبني فوق التجميع |
| ربط الصنف بـ رصد/GTIN دوائي | 🎭 صيدليات | يبني فوق التشغيلة |
| شروط التخزين (مبرّد/مجمّد) وسلسلة التبريد | 🎭 صيدليات + أغذية | يبني فوق Bins |
| الوزن المتغيّر (Catch Weight) | 🎭 لحوم/أغذية | يبني فوق وحدات القياس |

**الخلاصة:** ~٨٥٪ مما يبدو «مخزون صيدلية» أو «مخزون مطعم» هو في الحقيقة نواة.
ما يخصّ النشاط فعلاً هو **المعنى** لا **الآلية**.

# ٣. الوضع الحالي والفجوة

## ٣.١ الموجود فعلاً في mad-app

| العنصر | الحالة | الملاحظة |
|---|---|---|
| `Product` (اسم · سعر · تكلفة · وحدة · حد أدنى) | ✅ | حقل `cost` واحد ثابت — لا تاريخ ولا طبقات |
| `Warehouse` (اسم · موقع · مسؤول) | ✅ | بلا مواقع داخلية ولا ربط بفرع صريح |
| `StockMovement` (`IN`/`OUT`/`TRANSFER`/`ADJUSTMENT`) | ✅ | **كمية فقط — بلا قيمة وبلا قيد محاسبي** |
| رصيد الصنف بالمستودع | ✅ | يُحسب بالجمع على الحركات وقت العرض |
| فواتير الشراء والترحيل التلقائي | ✅ | **تُرحَّل لحساب مصروف مباشرة** |
| فواتير البيع والترحيل التلقائي | ✅ | تُرحَّل إيراداً بلا قيد تكلفة مقابل |

## ٣.٢ الفجوة الجوهرية — بجملة واحدة

> النظام اليوم يعرف **كم صنفاً لديك**، ولا يعرف **بكم**.

أثر ذلك ليس تجميلياً:

1. **لا وجود لتكلفة بضاعة مباعة.** قائمة الدخل تعرض إيراداً كاملاً مقابل مصروف مشتريات
   لا يطابق الفترة → **مجمل الربح خاطئ لكل عميل يبيع سلعاً**.
2. **الميزانية العمومية ناقصة أصلاً.** المخزون أصل متداول، وحين تُرحَّل المشتريات مصروفاً
   يختفي هذا الأصل من الميزانية.
3. **الوعاء الزكوي خاطئ.** المخزون السلعي عنصر مضاف في الوعاء الزكوي — غيابه يعني
   إقراراً زكوياً غير صحيح.
4. **الجرد بلا معنى محاسبي.** فرق الجرد يظهر ككمية، ولا يمكن ترجمته لخسارة/مكسب.
5. **لا يمكن قياس ربحية صنف أو فرع.** أي تقرير «أعلى المنتجات ربحاً» مستحيل بنيوياً.

## ٣.٣ لماذا لا يمكن تأجيل الإصلاح

جدول `StockMovement` سيمتلئ ببيانات عملاء حقيقيين. إضافة طبقة التقييم لاحقاً تعني
**إعادة احتساب تاريخي بأثر رجعي** على بيانات حيّة، مع فترات محاسبية مقفلة لا تقبل
التعديل (`SPEC §3.7` مبنيّ). التكلفة الآن: أيام. التكلفة بعد عشرة عملاء: مشروع كامل
مع مخاطر بيانات لا يمكن التراجع عنها.

# ٤. القرارات المعلَّقة ⛔

> لا يبدأ أي بناء في هذه الوحدة قبل حسم البنود الخمسة الأولى.

## ⛔ ق-١ — طريقة تقييم المخزون

| الخيار | يصلح لـ | التكلفة التقنية | الأثر |
|---|---|---|---|
| **المتوسط المرجح المتحرك** | تجزئة · مطاعم · قطع غيار | منخفضة — حقلان على رصيد الصنف | لا يتتبع أي طبقة اشتُريت |
| **FIFO بطبقات** | صيدليات · أغذية · مستوردون | متوسطة — جدول طبقات + منطق استهلاك | يعطي ربط تشغيلة/صلاحية بالتكلفة |
| **الاثنان، بإعداد لكل شركة** | المنصة متعددة الأنشطة | مرتفعة — واجهة تجريد فوق المحرّكين | يمنع تغيير الطريقة بعد أول قيد |

**الخيار الرابع الذي أوصي بعرضه للنقاش:** بناء المحرّك بـ**طبقات دائماً**، وجعل
«المتوسط المرجح» طريقة **استهلاك** فوق الطبقات لا بنية بديلة. أي: طبقة واحدة تُحدَّث
تكلفتها بالمتوسط عند كل استلام. هكذا يكون التحوّل بين الطريقتين تغييراً في دالة
الاستهلاك لا في المخطط، وتبقى التشغيلات والصلاحيات ممكنة في الحالتين.

**قيد نظامي:** معيار المخزون الدولي (IAS 2) المعتمد في السعودية عبر الهيئة السعودية
للمراجعين والمحاسبين **يمنع طريقة الوارد أخيراً صادر أولاً (LIFO)** ويجيز
الوارد أولاً صادر أولاً والمتوسط المرجح فقط. ويشترط **الثبات** في الطريقة، ولا يجيز
تغييرها إلا لمبرر يعطي معلومات أكثر موثوقية مع إفصاح عن الأثر.

**ما يترتب على القرار:** مخطط قاعدة البيانات · دالة الاستهلاك · تقرير تقييم المخزون ·
قدرة النظام على خدمة الصيدليات أصلاً.

## ⛔ ق-٢ — نظام الجرد: مستمر أم دوري

- **المستمر (Perpetual):** قيد تكلفة مع كل عملية بيع. دقيق لحظياً، وهو المعيار
  للأنظمة الحديثة، وشرط لأي تقرير ربحية لحظي.
- **الدوري (Periodic):** قيد تكلفة واحد في نهاية الفترة بعد الجرد الفعلي. أبسط،
  لكنه يترك قائمة الدخل بلا معنى داخل الفترة.

**الأثر:** عدد القيود يقفز من قيد لكل فاتورة إلى قيدين. في مطعم بألف فاتورة يومياً
هذا ٧٣٠ ألف قيد سنوياً لعميل واحد — مرتبط مباشرة بالقرار ق-٥ أدناه.

## ⛔ ق-٣ — تعريف «المستودع» مقابل «الفرع»

اليوم `Warehouse` كيان مستقل، و`Branch` كيان آخر (`SPEC §2.4` مبنيّ). الأسئلة:
- هل كل فرع يملك مستودعاً ضمنياً تلقائياً؟
- هل يمكن لمستودع أن يخدم عدة فروع (مستودع مركزي)؟
- الفرع الذي بلا مستودع مستقل — أين بضاعته؟

**الأثر:** `SPEC §2.5` (مخزون مستقل لكل فرع) مصنَّف 🔴 حرج ولا يمكن إغلاقه بلا هذا التعريف.

## ⛔ ق-٤ — تكلفة موحّدة أم تكلفة لكل مستودع

هل تكلفة الصنف واحدة على مستوى الشركة، أم لكل مستودع تكلفته المستقلة؟

| النموذج | نتيجته |
|---|---|
| تكلفة على مستوى الشركة | التحويل بين المستودعات بلا أثر قيمي إطلاقاً — أبسط |
| تكلفة لكل مستودع | يعكس تكلفة الشحن للفرع البعيد — أدق، لكنه يعقّد التحويلات |

## ⛔ ق-٥ — تفصيل القيد: لكل فاتورة أم مجمَّع

قيد تكلفة لكل فاتورة (دقيق، ثقيل) مقابل قيد مجمَّع لكل وردية/يوم (خفيف، يفقد الربط
المباشر). **مرتبط بقرار مماثل معلَّق في ملف المطاعم** — يُحسم مرة واحدة للنظامين.

## ق-٦ — بنود أصغر (يمكن حسمها لاحقاً)

| # | القرار | لماذا يمكن تأجيله |
|---|---|---|
| ٦أ | هل تُفعَّل المواقع الداخلية (Bins) في الإصدار الأول؟ | مفتاح تفعيل، لا يغيّر المخطط |
| ٦ب | هل يُسمح بالرصيد السالب؟ | إعداد لكل شركة |
| ٦ج | حد التقريب في تكلفة الوحدة (٤ خانات أم ٦) | يُحسم قبل أول قيد فقط |
| ٦د | هل يُبنى أمر الشراء (`SPEC §5.6`) في نفس الموجة؟ | يفيد كثيراً لكنه ليس شرطاً |

# ٥. نموذج البيانات

## ٥.١ المبدأ: الحركة قيد مزدوج

> كل حركة مخزون تُسجَّل كـ**سطرين**: من أين خرجت، وإلى أين دخلت.

هذا التصميم (المستخدم في الأنظمة الناضجة) يحلّ مشكلات كثيرة دفعة واحدة:
الاستلام = من «مورد افتراضي» إلى مستودع؛ البيع = من مستودع إلى «عميل افتراضي»؛
التالف = من مستودع إلى «موقع خسائر»؛ التحويل = من مستودع إلى مستودع.
**النتيجة:** منطق واحد لكل أنواع الحركة، ورصيد أي موقع = مجموع الداخل ناقص الخارج،
ولا حاجة لـ `if` منفصل لكل نوع كما في الكود الحالي.

المواقع الافتراضية (`VIRTUAL`) المطلوبة:
`SUPPLIER` · `CUSTOMER` · `INVENTORY_LOSS` · `PRODUCTION` · `IN_TRANSIT` · `SCRAP` · `INITIAL_BALANCE`

## ٥.٣ ثلاث قواعد لا تُخرق

1. **الكمية تُخزَّن دائماً بالوحدة الأساسية.** الوحدة المعروضة تحويل عرضي فقط.
   خرق هذه القاعدة يجعل كل تقرير مجموع تفاح وبرتقال.
2. **`StockMove` غير قابل للتعديل بعد `DONE`.** التصحيح بحركة عكسية، لا بتعديل.
   (يطابق `SPEC §3.5` — منع تعديل قيد مرحَّل.)
3. **`StockQuant` مشتق لا مصدر.** يجب أن يكون قابلاً لإعادة البناء بالكامل من
   `StockMove`. اختبار دوري يتحقق من التطابق.

# ٦. التقييم — المحرّك بالتفصيل

## ٦.١ ما الذي يدخل في التكلفة

معيار المخزون يوجب أن تشمل التكلفة **كل** ما أُنفق لإيصال البضاعة إلى موقعها وحالتها
الحاليين: سعر الشراء، ورسوم الاستيراد والضرائب غير القابلة للاسترداد، وتكاليف النقل
والمناولة، وأي تكلفة أخرى منسوبة مباشرة للاقتناء. ويُقاس المخزون بـ**التكلفة أو صافي
القيمة القابلة للتحقق أيهما أقل**.

| يُرسمل على المخزون ✅ | لا يُرسمل ❌ |
|---|---|
| سعر الشراء بعد الخصم | الضريبة القابلة للاسترداد (مدخلات) |
| الشحن الدولي والداخلي للوارد | تكاليف البيع والتوزيع للخارج |
| الرسوم الجمركية | مصاريف إدارية عامة |
| التأمين على الشحنة | تخزين البضاعة الجاهزة (إلا لضرورة إنتاجية) |
| التخليص والمناولة بالميناء | الفاقد غير الطبيعي |
| الفاقد الطبيعي المتوقع | فوائد التمويل (مصروف فائدة) |

## ٦.٢ مثال عددي — الفرق بين الطريقتين

الحركة: شراء ١٠٠ حبة × ١٠ ر.س، ثم ٢٠٠ × ١٢، ثم ١٥٠ × ١٤. ثم بيع ٣٠٠ حبة.

| | FIFO | المتوسط المرجح |
|---|---|---|
| إجمالي التكلفة المتاحة | ٦٫٥٠٠ (٤٥٠ حبة) | ٦٫٥٠٠ (٤٥٠ حبة) |
| تكلفة الوحدة | حسب الطبقة | ٦٫٥٠٠ ÷ ٤٥٠ = ١٤٫٤٤ |
| تكلفة المبيعات (٣٠٠) | (١٠٠×١٠)+(٢٠٠×١٢) = ٣٫٤٠٠ | ٣٠٠ × ١٤٫٤٤ = ٤٫٣٣٣ |
| مخزون آخر المدة (١٥٠) | ١٥٠ × ١٤ = ٢٫١٠٠ | ١٥٠ × ١٤٫٤٤ = ٢٫١٦٧ |
| **مجمل الربح** | **أعلى** | **أقل** |

> **الدرس:** الفرق بين الطريقتين على نفس البيانات هو ٩٣٣ ريالاً في مجمل الربح على
> صفقة واحدة. على مستوى سنة كاملة هذا فرق ضريبي وزكوي حقيقي. لذلك القرار ⛔ق-١
> ليس تفصيلاً تقنياً.

## ٦.٣ خوارزمية الاستهلاك (FIFO بطبقات)

```
عند صرف كمية Q من الصنف I من الموقع L:
  ١. اجلب الطبقات المتاحة (remainingQty > 0) مرتَّبة:
       - FIFO عادي     → حسب receiptDate تصاعدياً
       - FEFO (صلاحية) → حسب expiryDate تصاعدياً   ← ⭐ للصيدلية والأغذية
  ٢. استهلك تسلسلياً حتى تكتمل Q، مسجّلاً كل استهلاك في StockLayerConsumption
  ٣. إن نفدت الطبقات وبقيت كمية (رصيد سالب):
       أ. إن كان الرصيد السالب ممنوعاً → ارفض العملية
       ب. إن كان مسموحاً → أنشئ طبقة سالبة بآخر تكلفة معروفة، وسجّلها للتسوية
  ٤. تكلفة الصرف = مجموع (الكمية × تكلفة الطبقة) لكل طبقة مستهلكة
  ٥. أنشئ StockMove بـ totalValue = تكلفة الصرف
  ٦. أنشئ القيد المحاسبي المقابل (§١٩)
```

**القفل الإلزامي:** الخطوات ١–٦ داخل معاملة واحدة مع قفل على مستوى
(`itemId`, `locationId`) — وإلا فبيعتان متزامنتان تستهلكان الطبقة نفسها.

## ٦.٤ خوارزمية المتوسط المرجح المتحرك

```
عند استلام كمية Q بتكلفة C:
  التكلفة الجديدة = (الرصيد القديم × المتوسط القديم + Q × C) ÷ (الرصيد القديم + Q)
عند الصرف:
  تكلفة الصرف = الكمية × المتوسط الحالي  (المتوسط لا يتغيّر)
```

**الفخّ المعروف:** استلام يُدخَل بتاريخ سابق بعد أن صُرفت كميات لاحقة → المتوسط
المحسوب وقت الصرف صار خاطئاً بأثر رجعي. **الحل المعتمد:** منع الإدخال بأثر رجعي في
فترة فيها حركات لاحقة، أو تشغيل إعادة احتساب صريحة مع قيد تسوية مرئي للمستخدم.
لا يجوز التعديل الصامت.

## ٦.٥ صافي القيمة القابلة للتحقق (NRV) والانخفاض

معيار المخزون يوجب تخفيض المخزون إلى صافي القيمة القابلة للتحقق حين تقلّ عن التكلفة،
والاعتراف بالفرق خسارةً في قائمة الدخل. مسبّباتها: التلف، والتقادم الكلي أو الجزئي،
وانخفاض أسعار البيع، وارتفاع تكاليف الإتمام أو البيع.

**ما يبنيه النظام:**
- حقل `nrvPerUnit` اختياري على مستوى الصنف/التشغيلة
- تقرير «أصناف تكلفتها تفوق سعر بيعها الحالي» — كشف تلقائي
- تقرير تقادم المخزون (٠–٩٠ · ٩١–١٨٠ · ١٨١–٣٦٥ · +٣٦٥ يوماً بلا حركة)
- شاشة تكوين مخصص هبوط بقيمة يقرّها المستخدم → القيد ق-١٧
- **قاعدة نظامية:** يُعكس المخصص إذا زالت أسبابه — يجب أن يدعم النظام العكس، لا
  التخفيض فقط.

# ٧. وحدات القياس والتعبئة

## ٧.١ لماذا هذه نواة وليست ميزة جملة

الصيدلية تشتري بالكرتون وتبيع بالشريط وتصرف بالحبة. المطعم يشتري الزيت بالتنكة
ويستهلكه بالمليلتر. الجملة تبيع بالطبلية وبالكرتون وبالحبة بأسعار مختلفة.
**آلية واحدة، ثلاثة معانٍ.**

## ٧.٢ التصميم

```
UomCategory: عدد | وزن | حجم | طول | زمن
UnitOfMeasure: name, categoryId, factor (نسبة للوحدة المرجعية), rounding
ItemUom: itemId, uomId, factor, barcode, isPurchaseDefault, isSaleDefault
```

**القواعد:**
1. التحويل مسموح **داخل الفئة فقط**. كيلو ↔ جرام نعم؛ كيلو ↔ لتر لا (إلا بكثافة
   معرَّفة على الصنف — حالة الأغذية).
2. **الكسور والتقريب:** بيع ٣ حبات من كرتون = ٢٤ يعطي ٠٫١٢٥ كرتون. التخزين بالوحدة
   الأساسية (حبة) يحلّ هذا نهائياً.
3. **باركود لكل وحدة:** الكرتون له باركود والحبة لها باركود آخر. مسح أي منهما يجب
   أن يعطي الكمية الصحيحة تلقائياً.
4. **الوزن المتغيّر (Catch Weight):** قطعة لحم واحدة بوزن مختلف لكل قطعة — تحتاج
   حقلي كمية (عدد القطع + الوزن الفعلي). 🎭 ملف نشاط الأغذية، لكن الحقل يُترك في النواة.

## ٧.٣ الباركود و GS1

| المستوى | الوصف | الاستخدام |
|---|---|---|
| GTIN-13 / EAN-13 | معرّف المنتج التجاري | التجزئة — مسح الكاشير |
| GTIN-14 | معرّف العبوة الأكبر | الجملة — الكرتون |
| GS1-128 / DataMatrix | يحمل GTIN + تشغيلة + صلاحية + تسلسلي | 🔌 الصيدليات ورصد |
| SSCC | معرّف وحدة الشحن (الطبلية) | 🔌 اللوجستيات |

**قاعدة تحليل GS1-128:** النظام يجب أن يفكّ معرّفات التطبيق:
`(01)` GTIN · `(10)` رقم التشغيلة · `(17)` تاريخ الصلاحية · `(21)` الرقم التسلسلي ·
`(00)` SSCC. مسحة واحدة تملأ أربعة حقول — هذه فارقة عملية ضخمة في المستودع.

> **من دروس المشروع:** عضوية مركز الترقيم السعودي (GS1) شرط مسبق لتكامل رصد.
> تُبدأ إجراءاتها مبكراً لأنها إدارية بطيئة ولا تعتمد على الكود.

# ٨. التتبّع: تشغيلات · صلاحيات · أرقام تسلسلية

## ٨.١ ثلاثة أوضاع للصنف

| الوضع | المعنى | مثال |
|---|---|---|
| `NONE` | لا تتبّع — الحبّات متكافئة | مسامير · أكواب ورقية |
| `LOT` | تتبّع بالمجموعة | دواء · حليب · دهان |
| `SERIAL` | تتبّع بالوحدة الواحدة | جوّال · سيارة · مولّد |

**قاعدة:** الوضع يُحدَّد عند إنشاء الصنف و**لا يتغيّر بعد أول حركة**. تغييره لاحقاً
يترك أرصدة بلا تشغيلة لا يمكن ربطها.

## ٨.٢ الصلاحية و FEFO

- الصرف الافتراضي للأصناف ذات الصلاحية هو **الأقرب انتهاءً أولاً (FEFO)** لا FIFO.
  الطبقة الأقدم شراءً ليست بالضرورة الأقرب انتهاءً.
- **تجاوز FEFO** يجب أن يكون ممكناً (طلب عميل لتشغيلة محددة) لكن **مسجَّلاً بسبب**.
- **درجات التنبيه:** قابلة للإعداد لكل فئة (دواء ٩٠ يوماً · طعام ٧ أيام · مستحضر ١٨٠).
- **الحظر التلقائي:** التشغيلة المنتهية تُمنع من البيع تلقائياً وتُنقل لموقع حجر
  (`isQuarantine`) — لا تبقى في الرصيد المتاح.
- **الاستدعاء (Recall):** بحث عكسي — من رقم تشغيلة إلى كل فاتورة بيع خرجت منها،
  وكل عميل استلمها. 🔌 إلزامي للأدوية والأغذية.

## ٨.٣ الأرقام التسلسلية

- الرقم التسلسلي كيان له **تاريخ حياة**: استُلم بتاريخ · انتقل لموقع · بيع لعميل ·
  في الضمان حتى · عاد بمرتجع.
- **قيد صارم:** الكمية دائماً ١. أي حركة برقم تسلسلي وكمية ≠ ١ خطأ برمجي.
- الاستعلام المطلوب: «أين الرقم X الآن؟» و«ما تاريخ الرقم X كاملاً؟»

# ٩. دورة الشراء الكاملة

## ٩.١ المسار

```
طلب شراء داخلي → أمر شراء (PO) → استلام (GRN) → فحص جودة → إدخال المخزون
        → فاتورة المورد → المطابقة الثلاثية → السداد
```

**نقطة حاسمة:** المخزون يزيد عند **الاستلام**، لا عند الفاتورة. الفصل بينهما هو ما
يجعل الحسابات صحيحة في الفترة التي تصل فيها البضاعة قبل الفاتورة أو العكس.

## ٩.٢ حساب «مشتريات مستلمة غير مفوترة» (GRNI)

| الحالة | المعالجة |
|---|---|
| وصلت البضاعة، لم تصل الفاتورة | مخزون (مدين) / GRNI (دائن) — التزام حقيقي |
| وصلت الفاتورة، لم تصل البضاعة | بضاعة بالطريق (مدين) / دائنون (دائن) |
| وصلا معاً | GRNI (مدين) / دائنون (دائن) — يُقفَل الحساب |

**تقرير إلزامي:** رصيد GRNI المفتوح بعمره. رصيد قديم فيه يعني إما فاتورة ضائعة أو
استلاماً وهمياً — وهو من أكثر مؤشرات الاحتيال دلالة في المستودعات.

## ٩.٣ المطابقة الثلاثية (Three-Way Match)

مطابقة **أمر الشراء ↔ الاستلام ↔ الفاتورة** على: الصنف، الكمية، السعر.

| نوع الفرق | السلوك |
|---|---|
| كمية مستلمة < المطلوبة | استلام جزئي — الأمر يبقى مفتوحاً |
| كمية مستلمة > المطلوبة | يُقبل ضمن نسبة تسامح قابلة للإعداد (٥٪ مثلاً)، وإلا يُحجب |
| سعر الفاتورة ≠ سعر الأمر | **فرق سعر شراء** → يعدّل تكلفة الطبقة إن كانت لم تُستهلك، وإلا يذهب لحساب فروق أسعار الشراء |
| صنف بالفاتورة غير مستلم | يُرفض حتى التسوية |

## ٩.٤ مرتجع المشتريات

- المرتجع يخرج **من الطبقة نفسها التي دخل بها** — لا من الطبقة الأقدم. هذا ما يجعل
  الربط بالفاتورة الأصلية ضرورياً على `StockMove`.
- يستلزم **إشعاراً مديناً** من المورد للأثر الضريبي (§٢٠).
- **حالة حدّية:** مرتجع صنف بعد أن نفدت طبقته الأصلية بالبيع → تُعالج بحركة عكسية
  بتكلفة الطبقة المسجَّلة تاريخياً، لا بالتكلفة الحالية.

## ٩.٥ الخصومات

| النوع | المعالجة |
|---|---|
| خصم على السطر | يخفّض تكلفة الطبقة مباشرة |
| خصم على إجمالي الفاتورة | يُوزَّع على الأسطر بالقيمة تناسبياً |
| خصم سداد مبكر | ⚠️ **قرار محاسبي**: تخفيض تكلفة أم إيراد آخر؟ عملياً يُفضَّل تخفيض التكلفة إذا كان معلوماً وقت الشراء |
| خصم كمية لاحق (Rebate) | لا يعدّل الطبقات المستهلكة — يُسجَّل إيراداً/تخفيض تكلفة في فترته |

# ١٠. التكلفة الوصولية (Landed Cost)

## ١٠.١ لماذا هي فارقة في السوق السعودي

مستورد يشتري بضاعة بـ ١٠٠٫٠٠٠ ريال، ويدفع ٨٫٠٠٠ شحناً و ٥٫٠٠٠ جماركاً و ٢٫٠٠٠ تخليصاً
و ١٫٥٠٠ نقلاً داخلياً. تكلفته الحقيقية ١١٦٫٥٠٠ — أي **١٦٫٥٪ أعلى** من سعر الفاتورة.
النظام الذي يسجّل ١٠٠٫٠٠٠ فقط يجعل التاجر يظن أنه يربح وهو يخسر.

## ١٠.٢ التصميم

```
LandedCost (رأس):
├── date, refType (شحنة/فاتورة شراء), totalAmount
├── status: DRAFT | POSTED
└── lines[]

LandedCostLine:
├── costTypeId (شحن · جمارك · تأمين · تخليص · نقل داخلي · أخرى)
├── amount, supplierId, invoiceRef
└── allocationMethod: BY_VALUE | BY_QTY | BY_WEIGHT | BY_VOLUME | MANUAL
```

## ١٠.٣ قواعد التوزيع

| الطريقة | تناسب |
|---|---|
| بالقيمة | التأمين · الرسوم النسبية |
| بالكمية | الرسوم الثابتة لكل وحدة |
| بالوزن | الشحن البحري/البري |
| بالحجم | الشحن الحجمي (CBM) |
| يدوي | حالات خاصة — بصلاحية مقيّدة |

**قيود التنفيذ:**
1. التكلفة الوصولية تُطبَّق على **طبقات محددة**، وتزيد `unitCost` فيها.
2. **إن وصلت بعد بيع جزء من الشحنة:** الجزء المباع يُصحَّح بقيد فرق يذهب لتكلفة
   البضاعة المباعة في الفترة الحالية؛ الجزء المتبقي يعدَّل في الطبقة. لا يجوز تعديل
   قيد سابق في فترة مقفلة.
3. الضريبة المدفوعة بالجمارك **لا تُرسمل** إن كانت قابلة للاسترداد (§٢٠.٤).
4. **التقريب:** آخر سطر في التوزيع يستوعب فرق التقريب حتى يساوي المجموع القيمة الأصلية بالضبط.

# ١١. دورة البيع والصرف

## ١١.١ المسار وحالات الحجز

```
عرض سعر (لا أثر) → طلب مؤكَّد (حجز) → أمر تجهيز → انتقاء → تعبئة → شحن → تسليم (صرف فعلي)
```

| الكمية | التعريف |
|---|---|
| الفعلي (On Hand) | الموجود مادياً |
| المحجوز (Reserved) | مخصَّص لطلب مؤكَّد لم يُصرَف |
| **المتاح للبيع (Available)** | الفعلي − المحجوز |
| الوارد المتوقع (Incoming) | على أوامر شراء لم تُستلم |
| المتوقع (Forecast) | المتاح + الوارد − الطلبات المستقبلية |

> **الخطأ الشائع:** عرض «الفعلي» في شاشة البيع. النتيجة بيع بضاعة محجوزة لعميل آخر.
> **القاعدة:** شاشة البيع تعرض **المتاح** دائماً.

## ١١.٢ الصرف الجزئي والشحنات المتعددة

طلب بـ ١٠٠ حبة، متوفر ٦٠. الخيارات المطلوبة كإعداد: انتظار الاكتمال · شحن جزئي مع
إبقاء الباقي معلَّقاً · إلغاء الباقي. **الفوترة تتبع الصرف الفعلي لا الطلب.**

## ١١.٣ مرتجع المبيعات

```
طلب إرجاع → استلام → فحص → قرار: (صالح للبيع | تالف | إصلاح | إرجاع للمورد)
```

- **الصالح للبيع** يعود بـ**تكلفته الأصلية وقت البيع**، لا بالتكلفة الحالية. هذا
  يستلزم قراءة `StockLayerConsumption` للحركة الأصلية — وهو السبب الثاني لوجود ذلك الجدول.
- **التالف** يدخل موقع الهالك، ويُعترف به خسارةً.
- يستلزم **إشعاراً دائناً** إلكترونياً للأثر الضريبي (§٢٠.٣).

## ١١.٤ حالات خاصة

| الحالة | المعالجة |
|---|---|
| بيع بالسالب (طلب أكبر من الرصيد) | حسب إعداد ٦ب — الرفض هو الافتراضي الآمن |
| بضاعة عند العميل للتجربة | موقع `CUSTOMER_TRIAL` — تبقى ملكاً للشركة وتُدرَج في مخزونها |
| عينات مجانية | 🚨 **توريد مفترض ضريبياً** — راجع §٢٠.٥ |
| بيع بأقل من التكلفة | تحذير لا حظر، مع صلاحية تجاوز |

# ١٢. التحويلات بين المستودعات والفروع

## ١٢.١ المشكلة التي يحلّها «بضاعة بالطريق»

شاحنة تغادر مستودع الرياض يوم ١ وتصل جدة يوم ٣. في اليومين ٢ و ٣ البضاعة ليست في
أي مستودع. النظام الساذج يجعلها تختفي من الميزانية — أو تُحسب مرتين.

**الحل:** التحويل حركتان لا واحدة:
```
حركة ١: مستودع الرياض → موقع IN_TRANSIT   (يوم ١)
حركة ٢: موقع IN_TRANSIT → مستودع جدة       (يوم ٣)
```
رصيد `IN_TRANSIT` يظهر في تقرير مستقل، ويدخل الميزانية ضمن المخزون.

## ١٢.٢ قواعد التحويل

| القاعدة | التفصيل |
|---|---|
| الأثر على قائمة الدخل | **صفر** — نقل قيمة فقط، لا ربح ولا خسارة |
| الطبقات | تُنقل بتكلفتها كما هي (إن كانت التكلفة على مستوى الشركة) |
| التشغيلات | تُنقل بأرقامها — لا يجوز فقد ربط التشغيلة في التحويل |
| العجز عند الاستلام | فرق يُسجَّل خسارة في **مستودع الإرسال** بعد تحقيق |
| التحويل بين فروع بكيانات قانونية مختلفة | ⚠️ **بيع حقيقي** بفاتورة ضريبية — لا تحويل داخلي |
| صلاحية الاستلام | يجب أن يقرّها مستقبِل التحويل، لا مُرسِله |

## ١٢.٣ التحويل بين شركات مجموعة واحدة

هذا سؤال يتقاطع مع القرار المعلَّق `SPEC §15.9` (عدة أنشطة في حساب واحد). إن كان
الفرعان كيانين ضريبيين منفصلين فالتحويل توريد خاضع للضريبة، وإن كانا في مجموعة ضريبية
واحدة فالتوريدات بين أعضائها تُهمَل لأغراض الضريبة. **النظام يجب أن يعرف الحالتين.**

# ١٣. الجرد

## ١٣.١ ثلاثة أنماط

| النمط | الوصف | ملاءمة |
|---|---|---|
| **الجرد الكامل** | إيقاف الحركة وعدّ كل شيء | نهاية السنة المالية |
| **الجرد الدوري بالعيّنة (Cycle Counting)** | عدّ جزء يومياً بالتناوب بلا إيقاف | ⭐ الأفضل تشغيلياً |
| **جرد موجَّه بحدث** | عند وصول الرصيد صفراً أو عند شبهة | تكميلي |

## ١٣.٢ تصنيف ABC وجدولة العدّ

قاعدة التصنيف: نحو ٢٠٪ من الأصناف تمثّل ٨٠٪ من قيمة المخزون.

| الفئة | نسبة الأصناف | نسبة القيمة | تكرار العدّ المقترح |
|---|---|---|---|
| A | ~٢٠٪ | ~٨٠٪ | شهرياً |
| B | ~٣٠٪ | ~١٥٪ | ربع سنوي |
| C | ~٥٠٪ | ~٥٪ | سنوياً |

النظام يحسب التصنيف تلقائياً من حركة آخر ١٢ شهراً، ويولّد جدول عدّ يومياً.

## ١٣.٣ دورة الجرد في النظام

```
إنشاء ورقة جرد (نطاق: مستودع/فئة/فئة ABC)
   → ⭐ تجميد الرصيد المتوقع لحظة الإنشاء (snapshot)
   → إدخال العدّ الفعلي (يدوي أو بمسح باركود)
   → عرض الفروق بالكمية والقيمة
   → ⭐ مراجعة واعتماد بصلاحية أعلى من المُدخِل
   → ترحيل التسويات + القيد المحاسبي
```

**قواعد إلزامية:**
1. **العدّ الأعمى (Blind Count):** لا يُعرض الرصيد المتوقع للعادّ. عرضه يجعله يكتب
   ما يراه على الشاشة لا ما يراه على الرف.
2. **العادّ ≠ المعتمِد.** فصل الصلاحيتين هو الضابط الرقابي الأساسي.
3. **الحركة أثناء الجرد:** إما تُجمَّد على النطاق المجرود، أو تُسجَّل وتُعالَج بعد
   الاعتماد. المهم أن يكون السلوك محدَّداً لا مصادفة.
4. **عتبة التحقيق:** فرق يتجاوز نسبة/قيمة معيَّنة يستلزم سبباً مكتوباً وموافقة إضافية.
5. **العدّ المزدوج:** فرق كبير يستدعي إعادة عدّ قبل الترحيل.

## ١٣.٤ تصنيف أسباب الفروق

سرقة · كسر وتلف · خطأ استلام · خطأ صرف · خطأ إدخال · صنف في غير موقعه · انتهاء صلاحية
· فاقد طبيعي (تبخّر/جفاف) · غير معروف.

**التصنيف ليس ترفاً:** «فاقد طبيعي» و«سرقة» لهما معالجة ضريبية مختلفة (§٢٠.٥) وقيد
مختلف. وتقرير الأسباب عبر الفروع هو أداة الكشف الإداري الأهم.

يُحفظ في طبقة الملفات (MinIO — `SPEC §11.1` مبنيّة) ويُربط بالقيد.

# ١٥. المواقع الداخلية والانتقاء

## ١٥.١ شجرة المواقع

```
مستودع الرياض المركزي
├── منطقة الاستلام
```

## ١٥.٢ الانتقاء (Picking)

| الاستراتيجية | الوصف | تناسب |
|---|---|---|

| الانتقاء الدفعي | تجميع طلبات لنفس الصنف | طلبات صغيرة كثيرة |
| انتقاء المنطقة | كل عامل مسؤول عن منطقة | مستودع كبير |

**مسار الانتقاء الأمثل:** ترتيب سطور أمر الانتقاء حسب تسلسل المواقع فعلياً لا حسب
ترتيب الطلب — يقلّل مسافة المشي بشكل ملموس. هذه ميزة ⚪ مؤجَّلة لكن التصميم يجب
أن يسمح بها (ترتيب فرز على `StockLocation`).

# ١٦. التجميع والتفكيك (Kits / Bundles)

## ١٦.١ ثلاثة نماذج مختلفة تماماً

| النموذج | السلوك المخزني | مثال |
|---|---|---|
| **حزمة عرض (Bundle)** | لا صنف جديد — تُصرَف المكوّنات عند البيع | «اشترِ ٣ واحصل على…» |
| **تجميع فعلي (Kit)** | صنف جديد له رصيد؛ المكوّنات تُستهلك عند التجميع | سلة هدايا · طقم أدوات |
| **تفكيك (Unbundle)** | صنف واحد يُفكَّك لعدة أصناف | ذبيحة كاملة → قطعيات |

## ١٦.٢ قواعد التكلفة

- **التجميع:** تكلفة الصنف المجمَّع = مجموع تكاليف المكوّنات المستهلكة + تكلفة عمالة
  اختيارية. تُنشأ طبقة جديدة للمجمَّع، وتُستهلك طبقات المكوّنات.
- **التفكيك:** تكلفة الأصل تُوزَّع على النواتج بـ**نسبة القيمة البيعية النسبية** —
  وهي الطريقة المعيارية لتوزيع تكلفة مشتركة. التوزيع بالوزن يعطي نتائج مضلّلة
  (الفيليه والعظم ليسا متساويين بالكيلو).
- **قاعدة الاتزان:** إجمالي قيمة النواتج = قيمة المدخلات ± فاقد معرَّف. أي فرق آخر خطأ.

> هذه الوحدة هي **الأساس الذي تبني عليه وصفات المطاعم وأوامر التصنيع** — وهي السبب
> في تصنيفها نواة رغم أنها تبدو خاصة بنشاط.

# ١٧. بضاعة الأمانة والطرف الثالث

## ١٧.١ أربع حالات ملكية مختلفة

| الحالة | المخزون في ميزانية مَن | المعالجة |
|---|---|---|
| بضاعتي في مستودعي | أنا | عادي |
| **بضاعتي لدى وكيل/معرض** | أنا | موقع `CONSIGNMENT_OUT` — تبقى في مخزوني |
| **بضاعة الغير لديّ للبيع بالعمولة** | المورد | موقع `CONSIGNMENT_IN` — ⚠️ **لا تدخل ميزانيتي** |
| **بضاعة عميل مخزَّنة لديّ (3PL)** | العميل | خارج المخزون تماماً — عقد خدمة |

## ١٧.٢ لماذا هذا مهم محاسبياً وزكوياً

إدراج بضاعة الأمانة الواردة في الميزانية **يضخّم الأصول ويضخّم الوعاء الزكوي بلا وجه
حق**. وحذف بضاعة الأمانة الصادرة يفعل العكس. القاعدة الحاكمة: **الملكية لا الحيازة**.

## ١٧.٣ نموذج شركة التخزين (3PL)

نشاط مستقل يستحق ملف نشاط لاحقاً: تخزين بضائع الغير مقابل رسوم.
- المخزون كله ليس ملكاً للشركة — يُتتبَّع كمياً بلا قيمة في دفاترها
- الإيراد من: مساحة التخزين (لكل طبلية/متر مكعب/شهر) + المناولة (لكل حركة) +
  خدمات إضافية (تعبئة · لصق · إعادة تغليف)
- **التوقيت:** يُبنى بعد استقرار النواة. البنية هنا تدعمه (موقع بمالك مختلف).

# ١٨. التخطيط وإعادة الطلب

## ١٨.١ المعادلات

```
نقطة إعادة الطلب  = (متوسط الاستهلاك اليومي × مدة التوريد بالأيام) + المخزون الآمن

المخزون الآمن     = عامل الأمان × الانحراف المعياري للطلب × جذر(مدة التوريد)
                    (مبسَّطاً: متوسط الاستهلاك × أيام احتياطية)

الكمية الاقتصادية = جذر( (٢ × الطلب السنوي × تكلفة الأمر) ÷ تكلفة الاحتفاظ للوحدة )
```

## ١٨.٢ مستويات النضج — تُبنى بالتدريج

| المستوى | الوصف | الأولوية |
|---|---|---|
| ١ | حد أدنى/أقصى ثابت يدوي **لكل مستودع** | 🟠 |
| ٢ | نقطة إعادة طلب محسوبة من الاستهلاك الفعلي | 🟠 |
| ٣ | توليد اقتراح أمر شراء تلقائي (لا إرسال تلقائي) | 🟡 |
| ٤ | تنبؤ موسمي (رمضان · العودة للمدارس · الصيف) | ⚪ |
| ٥ | تنبؤ إحصائي/تعلّم آلي | ⚪ |

> **ملاحظة على المستوى ٤:** الموسمية في السوق السعودي **هجرية جزئياً** (رمضان والحج
> يتحركان في التقويم الميلادي). أي نموذج تنبؤ يعتمد «نفس الشهر من العام الماضي»
> سيفشل. يجب أن يدعم النظام التقويمين.

## ١٨.٣ مؤشرات يجب أن يحسبها النظام

| المؤشر | المعادلة | ما يكشفه |
|---|---|---|
| معدل دوران المخزون | تكلفة المبيعات ÷ متوسط المخزون | كفاءة رأس المال |
| أيام المخزون (DIO) | ٣٦٥ ÷ معدل الدوران | كم شهراً من البضاعة راكد |
| نسبة نفاد المخزون | مرات النفاد ÷ الطلبات | مبيعات ضائعة |
| المخزون الميت | أصناف بلا حركة > س يوماً | رأس مال مجمَّد |
| دقة المخزون | تطابق العدّ مع الدفتري | جودة العمليات |
| هامش الربح لكل صنف | (البيع − التكلفة) ÷ البيع | ⭐ مستحيل بلا §٦ |

## ١٩.٢ القيود — الجرد المستمر

> كل قيد أدناه يجب أن يكون له اختبار آلي مقابل قبل اعتماد الموجة.

**ق-١ — استلام بضاعة بأمر شراء (قبل الفاتورة)**
```
من ح/ ١٣١٠ مخزون بضاعة جاهزة              (بتكلفة الاستلام)
    إلى ح/ ٢١٥٠ مشتريات مستلمة غير مفوترة
```

**ق-٢ — استلام فاتورة المورد المطابقة**
```
من ح/ ٢١٥٠ مشتريات مستلمة غير مفوترة
من ح/ ١٢٥٠ ضريبة مدخلات
    إلى ح/ ٢١٠٠ الذمم الدائنة
```

**ق-٣ — شراء مباشر (بضاعة وفاتورة معاً)**
```
من ح/ ١٣١٠ مخزون
من ح/ ١٢٥٠ ضريبة مدخلات
    إلى ح/ ٢١٠٠ الذمم الدائنة (أو الصندوق/البنك)
```
> ⚠️ هذا القيد هو ما يحلّ محل السلوك الحالي في النموذج (ترحيل الشراء مصروفاً مباشرة).

**ق-٤ — تكلفة وصولية (شحن/جمارك) تُرسمل**
```
من ح/ ١٣١٠ مخزون                          (بمبلغ التوزيع)
    إلى ح/ ٢١٠٠ الذمم الدائنة — شركة الشحن/التخليص
```

**ق-٥ — تكلفة وصولية وصلت بعد بيع جزء من الشحنة**
```
من ح/ ١٣١٠ مخزون          (حصة الكمية المتبقية)
من ح/ ٥١١٠ تكلفة البضاعة المباعة  (حصة الكمية المباعة)
    إلى ح/ ٢١٠٠ الذمم الدائنة
```

**ق-٦ — البيع: الإيراد**
```
من ح/ ١٢٠٠ الذمم المدينة (أو الصندوق)
    إلى ح/ ٤١٠٠ إيرادات المبيعات
    إلى ح/ ٢١٦٠ ضريبة مخرجات
```

**ق-٧ — البيع: التكلفة** ⭐ *(القيد الغائب اليوم)*
```
من ح/ ٥١١٠ تكلفة البضاعة المباعة
    إلى ح/ ١٣١٠ مخزون
```
> يُرحَّل بقيمة الطبقات المستهلكة فعلياً حسب §٦.٣ — لا بسعر التكلفة الثابت على الصنف.

**ق-٨ — مرتجع مبيعات (الإيراد)**
```
من ح/ ٤١٥٠ مردودات المبيعات
من ح/ ٢١٦٠ ضريبة مخرجات
    إلى ح/ ١٢٠٠ الذمم المدينة
```

**ق-٩ — مرتجع مبيعات (التكلفة — بضاعة صالحة)**
```
من ح/ ١٣١٠ مخزون          (بالتكلفة الأصلية وقت البيع)
    إلى ح/ ٥١١٠ تكلفة البضاعة المباعة
```

**ق-١٠ — مرتجع مبيعات (بضاعة تالفة)**
```
من ح/ ٥١٣٠ تالف وهالك
    إلى ح/ ٥١١٠ تكلفة البضاعة المباعة
```

**ق-١١ — مرتجع مشتريات**
```
من ح/ ٢١٠٠ الذمم الدائنة
    إلى ح/ ١٣١٠ مخزون
    إلى ح/ ١٢٥٠ ضريبة مدخلات
```

**ق-١٢ — تحويل بين مستودعين (تكلفة على مستوى الشركة)**
```
لا قيد محاسبي — حركة كمية فقط
```

**ق-١٣ — تحويل بين مستودعين (تكلفة لكل مستودع) / بين فروع بحسابات منفصلة**
```
من ح/ ١٣١٠ مخزون — الفرع المستلم
    إلى ح/ ١٣١٠ مخزون — الفرع المرسل
```

**ق-١٤ — إخراج بضاعة للطريق (تحويل بعيد)**
```
من ح/ ١٣١٦ بضاعة بالطريق — داخلي
    إلى ح/ ١٣١٠ مخزون — الفرع المرسل
```
وعند الاستلام يُعكس إلى مخزون الفرع المستلم.

**ق-١٥ — فرق جرد بالزيادة**
```
من ح/ ١٣١٠ مخزون
    إلى ح/ ٥١٢٠ فروق الجرد
```

**ق-١٦ — فرق جرد بالنقص**
```
من ح/ ٥١٢٠ فروق الجرد
    إلى ح/ ١٣١٠ مخزون
```

**ق-١٧ — تالف/انتهاء صلاحية**
```
من ح/ ٥١٣٠ تالف وهالك
    إلى ح/ ١٣١٠ مخزون
```

**ق-١٨ — تكوين مخصص هبوط (NRV)**
```
من ح/ ٥١٤٠ مصروف هبوط وتقادم
    إلى ح/ ١٣١٩ مخصص هبوط المخزون
```

**ق-١٩ — عكس المخصص عند زوال سببه**
```
من ح/ ١٣١٩ مخصص هبوط المخزون
    إلى ح/ ٥١٤٠ مصروف هبوط وتقادم
```

**ق-٢٠ — استخدام داخلي (بضاعة تُستهلك في التشغيل)**
```
من ح/ ٥٣٠٠ مصروفات إدارية وعمومية (أو الحساب المناسب)
    إلى ح/ ١٣١٠ مخزون
```

**ق-٢١ — عيّنة مجانية / هدية (توريد مفترض)**
```
من ح/ ٥٣٠٠ مصروف تسويق
    إلى ح/ ١٣١٠ مخزون
        وقيد ضريبي مصاحب:
من ح/ ٥٣٠٠ مصروف ضريبة توريد مفترض
    إلى ح/ ٢١٧٠ ضريبة مستحقة على توريد مفترض
```
> راجع §٢٠.٥ — تفاصيل الحالات المستثناة.

**ق-٢٢ — فرق سعر شراء (الفاتورة ≠ الأمر، والطبقة استُهلكت)**
```
من ح/ ٥١٥٠ فروق أسعار الشراء
    إلى ح/ ٢١٠٠ الذمم الدائنة
```

**ق-٢٣ — تجميع صنف من مكوّنات**
```
من ح/ ١٣١٠ مخزون — الصنف المجمَّع
    إلى ح/ ١٣١١ مخزون — المكوّنات
```

**ق-٢٤ — استلام بضاعة أمانة (بضاعة الغير)**
```
لا قيد في دفاتر الحائز — تُتتبَّع كمياً فقط
(وعند بيعها: يُعترف بالعمولة إيراداً، لا بقيمة البيع كاملة)
```

**ق-٢٥ — أرصدة افتتاحية للمخزون عند بدء الاستخدام**
```
من ح/ ١٣١٠ مخزون
    إلى ح/ ٣٩٠٠ حساب الأرصدة الافتتاحية
```

# ٢٠. الضريبة والامتثال السعودي

## ٢٠.١ ما يخصّ المخزون تحديداً

الفوترة الإلكترونية مبنيّة أصلاً في المنصة (`SPEC §6.3–6.5`). ما يضيفه المخزون فوقها:

| البند | المطلوب |
|---|---|
| بيان الصنف في الفاتورة | وصف · كمية · وحدة · سعر وحدة — تتولّد من سطر المخزون |
| إشعار دائن للمرتجع | إلزامي إلكترونياً، مربوط بالفاتورة الأصلية |
| إشعار مدين لفرق السعر | كذلك |
| الاستيراد | ضريبة الاستيراد تُسدَّد جمركياً وتُخصم مدخلات — لا تُرسمل |
| التصدير | خاضع لنسبة الصفر بشروط، منها إخراج البضاعة خارج الإقليم خلال ٩٠ يوماً والاحتفاظ بمستندات التصدير الجمركية |

## ٢٠.٢ حفظ السجلات — التزام بنيوي على المنصة

- الفواتير الإلكترونية والإشعارات الدائنة والمدينة وكل سجل محاسبي داعم للإقرار
  الضريبي تُحفظ **٦ سنوات**، بصيغتها الأصلية، **داخل المملكة**.
- السجلات الزكوية تُحفظ مدة أطول (يُشار عملياً إلى ١٠ سنوات).

> 🚨 **أثر معماري مباشر:** هذا يتقاطع مع القرار المعلَّق حول **موقع الخوادم** المسجَّل
> في قرارات المشروع. حفظ سجلات ضريبية خارج المملكة مخاطرة امتثال. القرار بنية تحتية
> لا ميزة، ويجب حسمه قبل أول عميل حقيقي لا قبل أول سطر كود.
>
> 🚨 **أثر ثانٍ:** سلة المحذوفات (`SPEC §12.6`) والحذف النهائي يجب أن يستثنيا
> السجلات الضريبية خلال مدة الحفظ. لا يجوز أن يحذف التاجر ما يلزمه الاحتفاظ به.

## ٢٠.٣ المرتجعات والإشعارات

كل مرتجع مبيعات يستلزم إشعاراً دائناً إلكترونياً مربوطاً بالفاتورة الأصلية. النظام
يجب أن يمنع تسجيل مرتجع بلا إصدار الإشعار — وإلا حصل فرق بين دفتر المبيعات والإقرار.

## ٢٠.٤ ضريبة المدخلات على المخزون

- تُخصم في فترة الشراء، لا في فترة البيع.
- **لا تُرسمل على تكلفة المخزون** ما دامت قابلة للاسترداد — معيار المخزون صريح في
  استثناء الضرائب القابلة للاسترداد من التكلفة.
- **الاستثناء:** المنشأة ذات النشاط المعفى جزئياً — الجزء غير القابل للخصم **يُرسمل**.
  النظام يحتاج نسبة خصم نسبي على مستوى الشركة.

## ٢٠.٥ التوريد المفترض — أخطر بند مخزني ضريبياً 🚨

من حالات التوريد المفترض: تقديم السلع **دون مقابل** خارج سياق العمل، والاحتفاظ
بالسلع بعد انتهاء النشاط أو فقدان أهلية التسجيل — وفيها يُعدَّل حساب ضريبة المدخلات
التي سبق استردادها. وتُقيَّم بالقيمة السوقية العادلة.

| حالة مخزنية | توريد مفترض؟ |
|---|---|
| عيّنة مجانية للعميل | ✅ غالباً — إلا ضمن استثناء الهدايا منخفضة القيمة |
| «اشترِ واحدة واحصل على الثانية مجاناً» | ⚠️ يُعامل كخصم على التوريد المرتبط لا كهدية منفصلة |
| بضاعة يستهلكها المالك شخصياً | ✅ نعم |
| بضاعة تُستخدم داخلياً في نشاط خاضع | ❌ عموماً لا |
| تالف موثَّق بمحضر إتلاف | ❌ ليس توريداً — لكن التوثيق شرط |
| سرقة موثَّقة ببلاغ | ❌ ليس توريداً — مع البلاغ |
| نقص جرد غير مبرَّر | ⚠️ عرضة للاعتراض في الفحص |
| بضاعة متبقية عند إلغاء التسجيل | ✅ نعم بالقيمة السوقية |

**ما يبنيه النظام:** علم (flag) على نوع التسوية يحدد إن كانت تولّد ضريبة مخرجات،
وتقرير «التوريدات المفترضة في الفترة» يغذّي الإقرار.

> ⚠️ **هذا البند وما يليه يحتاجان مراجعة مستشار ضريبي معتمد قبل البناء.** الملف يصف
> الآلية المطلوبة في النظام، ولا يقوم مقام رأي ضريبي.

## ٢٠.٦ الزكاة — أثر المخزون على الوعاء

- المخزون السلعي (عروض التجارة) يشمل البضائع والمواد الخام والإنتاج تحت التشغيل
  والمنتجات التامة المحتفظ بها للمتاجرة.
- نسبة الزكاة الشرعية ٢٫٥٪ على الوعاء، والوعاء ليس الربح المحاسبي بل صافي الأموال
  المتاحة للاستثمار التي حال عليها الحول.
- **ملاحظة عملية موثَّقة:** الهيئة ترفض بشكل متزايد الإقرارات التي تفتقر إلى تفصيلات
  الأصول الزكوية والجداول الداعمة، ويُوصى بوجود عملية تقييم مخزون في نهاية العام
  توثَّق طريقتها وتُطبَّق باتساق.

**ما يبنيه النظام:** تقرير «تقييم المخزون في تاريخ محدد» بتفصيل الصنف والكمية
والتكلفة والقيمة — قابل للتصدير كجدول داعم للإقرار الزكوي. هذه ميزة بيعية حقيقية،
لأن معظم أصحاب المنشآت يعدّونها يدوياً في إكسل اليوم.

> تطبيقاً لقاعدة الفاعل الإلزامية (`CLAUDE.md` §3.5).

| الفعل | الفاعل | ملاحظة |
|---|---|---|
| إنشاء الأصناف والفئات | مالك المنشأة (أو مفوَّض) | ليس أمين المستودع |
| **تحديد طريقة التقييم** | مالك المنشأة | مرة واحدة، ثم تُقفل |

| صرف بضاعة | أمين المستودع | |

| **اعتماد فروق الجرد** | مدير المخزون / المالك | ⛔ ≠ العادّ |
| تسوية يدوية للرصيد | مدير المخزون | ⛔ بسبب إلزامي + سجل |
| إتلاف بضاعة | مدير + محضر | |

1. مَن يشتري ≠ مَن يستلم ≠ مَن يعتمد الدفع.
2. مَن يعدّ ≠ مَن يعتمد الفرق.
3. كل تسوية يدوية تدخل سجل التدقيق بمُدخِلها ووقتها وسببها وقيمتها.
4. تقرير دوري: أكثر المستخدمين إجراءً لتسويات يدوية — مؤشر إنذار مبكر.

# ٢٣. الجوانب التقنية الحرجة

## ٢٣.١ التزامن والقفل

سيناريو الفشل: كاشيران يبيعان آخر قطعة في اللحظة نفسها. الاثنان يقرآن الرصيد ١،
والاثنان يبيعان، والرصيد يصير −١ وتُستهلك الطبقة مرتين.

**الحل:** قفل تشاؤمي على مستوى الصف `(itemId, locationId)` داخل معاملة قاعدة البيانات
تشمل: قراءة الرصيد، استهلاك الطبقات، إنشاء الحركة، إنشاء القيد. لا شيء منها خارج
المعاملة.

## ٢٣.٢ الأداء

| المشكلة | الحل |
|---|---|
| حساب الرصيد بالجمع على ملايين الحركات (السلوك الحالي) | جدول `StockQuant` مُحدَّث لحظياً |
| طبقات كثيرة جداً لصنف سريع الحركة | أرشفة الطبقات المستنفدة دورياً |
| تقرير تقييم بتاريخ سابق | لقطات (snapshots) شهرية + احتساب الفرق |
| قيد لكل فاتورة في مطعم | ⛔ق-٥ — التجميع لكل وردية |
| فهارس | `(companyId, itemId, locationId, date)` · `(lotId)` · `(refType, refId)` |

## ٢٣.٣ عدم التكرار (Idempotency)

مسح باركود مرتين، أو ضغط «حفظ» مرتين، أو إعادة محاولة من الشبكة — كلها تنتج حركة
مكرَّرة. **الحل:** مفتاح تفرّد على (`refType`, `refId`, `lineId`) لكل حركة مولَّدة
تلقائياً + مفتاح عدم تكرار على واجهة الاستلام اليدوي.

## ٢٣.٤ الترحيل من الوضع الحالي (Migration)

هذه أخطر خطوة تقنية في الخطة:

```
١. أنشئ البنية الجديدة جنباً إلى جنب مع القديمة
٢. لكل صنف: احسب الرصيد الحالي من StockMovement القائم
٣. أنشئ طبقة افتتاحية واحدة لكل (صنف × مستودع) بالتكلفة المتاحة
     - المصدر الأول: حقل cost على Product
     - المصدر الثاني: آخر فاتورة شراء للصنف
     - إن لم يوجد: ⚠️ صفر + تقرير «أصناف بلا تكلفة» يعرضه على المستخدم للتصحيح
٤. رحّل قيداً افتتاحياً واحداً بقيمة المخزون (ق-٢٥)
٥. شغّل النظامين بالتوازي فترة، وقارن الأرصدة يومياً
٦. أوقف القديم بعد تطابق كامل
```

> **قاعدة:** لا يُحتسب تاريخ سابق بأثر رجعي. الطبقة الافتتاحية نقطة صفر معلنة
> وموثَّقة للمستخدم، لا محاولة لإعادة بناء ماضٍ لا تملك بياناته.

# ٢٤. الحالات الحدّية

| # | الحالة | المعالجة |
|---|---|---|
| ح-١ | بيع صنف رصيده صفر | يُرفض افتراضياً؛ إن سُمح فطبقة سالبة + تنبيه |
| ح-٢ | استلام بتاريخ سابق بعد صرف لاحق | يُمنع في فترة مقفلة؛ يُعاد الاحتساب صراحةً مع قيد تسوية |
| ح-٣ | تحويل بضاعة تنتهي صلاحيتها أثناء الطريق | تنبيه عند الإرسال + حظر الاستلام في المتاح |
| ح-٤ | جرد وحركة بيع في اللحظة نفسها | تجميد النطاق المجرود أو معالجة الحركات بعد الاعتماد |
| ح-٥ | تشغيلتان بنفس الرقم من موردين مختلفين | مفتاح التفرّد = (صنف + رقم التشغيلة + المورد) |
| ح-٦ | مرتجع صنف بيع بخصم | التكلفة ترجع كاملة؛ الخصم أثره على الإيراد فقط |
| ح-٧ | صنف غيّر وحدة قياسه بعد وجود رصيد | يُمنع؛ الحل صنف جديد أو تحويل موثَّق |
| ح-٨ | مورد يسلّم صنفاً بديلاً | يُستلم كصنف مختلف بموافقة، لا كالصنف المطلوب |
| ح-٩ | كسر عبوة كبيرة لبيع أجزائها | حركة تفكيك (§١٦) لا تعديل رصيد |
| ح-١٠ | بضاعة وصلت بلا أمر شراء | تدخل موقع الحجر حتى تسوية إدارية |
| ح-١١ | صنف بتكلفة صفر (هدية من المورد) | مسموح لكن يُعلَّم ويظهر في تقرير مستقل |
| ح-١٢ | حذف صنف له حركات | يُمنع؛ يُؤرشَف فقط (`SPEC §12.6`) |
| ح-١٣ | فاتورة مورد بعملة أجنبية | التكلفة بالعملة الأساسية بسعر يوم الاستلام؛ فروق السداد على ٥٦٠٠ |
| ح-١٤ | تحويل يستلمه المستودع ناقصاً | العجز خسارة في المستودع المرسل بعد تحقيق |
| ح-١٥ | إغلاق فرع ونقل مخزونه | تحويل جماعي موثَّق، لا حذف |

# ٢٥. معايير القبول

> لا تُعتبر الموجة منجزة قبل نجاح كل بند بلا استثناء.

**المحاسبية**
- [ ] رصيد ح/١٣١٠ في ميزان المراجعة = إجمالي تقرير تقييم المخزون، في أي تاريخ
- [ ] كل `StockMove` بقيمة له `journalEntryId` غير فارغ
- [ ] مجمل الربح المحسوب = المبيعات − ق-٧ متراكماً، مطابقاً لقائمة الدخل
- [ ] `StockQuant` قابل لإعادة البناء بالكامل من `StockMove` بلا فرق
- [ ] لا يمكن ترحيل أي حركة في فترة مقفلة

**التقييمية**
- [ ] المثال العددي في §٦.٢ ينتج نفس الأرقام بالضبط في الاختبار الآلي
- [ ] الصرف من صنف بصلاحية يستهلك الأقرب انتهاءً لا الأقدم شراءً
- [ ] التكلفة الوصولية توزَّع بمجموع يساوي المبلغ الأصلي (فرق التقريب = صفر)
- [ ] مرتجع البيع يعود بالتكلفة الأصلية لا الحالية

**التزامنية**
- [ ] ١٠٠ عملية بيع متزامنة لآخر قطعة → واحدة تنجح و٩٩ تُرفض بوضوح
- [ ] إعادة إرسال الطلب نفسه مرتين لا تنشئ حركتين

**التشغيلية**
- [ ] العادّ لا يرى الرصيد المتوقع في شاشة الجرد
- [ ] العادّ لا يستطيع اعتماد فروقه
- [ ] كل تسوية يدوية لها سبب وسجل تدقيق
- [ ] الموظف لا يرى مخزون فرع غير فرعه إلا بصلاحية

**الامتثالية**
- [ ] كل مرتجع مبيعات يولّد إشعاراً دائناً مربوطاً بالفاتورة الأصلية
- [ ] تقرير التوريدات المفترضة يعرض العيّنات والاستخدامات الشخصية
- [ ] تقرير تقييم المخزون قابل للتصدير كجدول داعم للإقرار
- [ ] السجلات الضريبية لا تُحذف نهائياً خلال مدة الحفظ النظامية
